# Private Railway deployment

The included Docker image runs one Streamlit process behind Caddy. Railway supplies HTTPS; Caddy requires
the owner's username and password on app pages, static photos, media and WebSocket connections. Streamlit
listens only on loopback and also checks a private proxy token. Only the exact GET/HEAD `/_stcore/health`
endpoint is public. Missing login secrets stop startup.

## Service configuration

Connect your own GitHub repository to one Railway service. Railway detects the repository's root `Dockerfile`.
Save these settings on the service's **Settings** page before deploying:

| Setting | Value |
|---|---|
| Dockerfile path | `Dockerfile` |
| Healthcheck path | `/_stcore/health` |
| Healthcheck timeout | `120` seconds |
| Restart policy | `On Failure` |
| Maximum restart retries | `10` |
| Replicas | `1` |
| Railway Config File | Leave blank |

These values live in Railway's service settings. The repository does not use the deprecated
`railway.toml`/`railway.json` configuration format or require a Railway IaC SDK. If migrating an older
deployment, save the service settings before clearing its Railway Config File path; legacy file values do
not populate those settings automatically. See [Railway's configuration guidance](https://docs.railway.com/config-as-code).

Attach one persistent volume at `/data`; the app stores its SQLite database, photos, backups, exports,
logs and saved preferences there. Keep one replica. The repository and image exclude working inventory,
photos and credentials.

Set these service variables before deploying:

| Variable | Value |
|---|---|
| `PORT` | `8080` |
| `RIVIAN_FINDER_CLOUD` | `1` |
| `RIVIAN_FINDER_DATA_DIR` | `/data` |
| `TZ` | Your IANA timezone, for example `America/Denver` |
| `TRUCK_FINDER_USER` | Your private login username |
| `TRUCK_FINDER_PASSWORD_HASH` | A bcrypt hash generated by `caddy hash-password` |
| `TRUCK_FINDER_PROXY_SECRET` | A separate long, randomly generated secret |
| `AUTODEV_API_KEY` | Your provider key, when used |
| `MARKETCHECK_API_KEY` | Your provider key, when used |
| `TRUCK_FINDER_IMAP_PASSWORD` | Mailbox app password, when importing alert emails automatically |

Use Railway's secret variables or CLI stdin input. Keep the plaintext login password privately in your
password manager. Do not commit secrets or put them in deployment commands, URLs or screenshots. The app's
credentials page reports which keys are configured; cloud credentials are managed in Railway.

Deploy, generate a Railway domain targeting port 8080, then verify that anonymous page/photo/media requests
are denied while authenticated navigation works. A passing health check confirms the server is running;
also check the actual signed-in app before treating a deployment as ready.

## Move an existing workspace

Create a consistent SQLite backup with the app's backup tool or SQLite's backup API. Move that database and
the `data/photos/` directory privately to the volume before the first app startup. Preserve the full database
to retain notes, checklists, contacts, evidence, favorites and API usage counters. A JSON export does not
contain every runtime table. Reset a Windows-specific export-folder preference to the default cloud folder.

Do not overwrite a running SQLite database. For a later restore, stop the service, preserve the current
database, replace it with a validated backup, and restart. The hosted UI disables live restore and provides a
downloadable consistent database backup. Enable Railway volume backups as a second recovery option.

Local and hosted copies do not synchronize. Use the hosted copy after migration and turn off any old desktop
scheduled searches so two copies do not independently spend the same provider quota.

## Scheduling and desktop features

Hosted scheduling runs in the server process and reads **Settings → Alerts**. It uses your saved enabled flag,
times and `TZ`, respects provider budgets, and waits for a future scheduled time after a restart. It does not
catch up missed runs or start a search merely because someone opens the app. Keep scheduling disabled if you
prefer selecting brands manually with **Run Search**.

Manual and scheduled searches are serialized, and browser sessions use separate database connections. Results
remain in Dashboard and refresh history. Desktop notifications are not phone push notifications. The browser
capture extension still targets the local computer; paste/import capture works on the hosted app.

## Mobile

Inventory cards fit narrow screens, stack photos above details and provide larger touch targets. Search,
refresh and selected-vehicle actions are available in the main page. **Compare → Compact comparison** shows
the essential rows without the full photo and financing layout. Wide tables can still scroll horizontally.

This deployment is one private shopping workspace. It does not separate inventory or preferences between
multiple independent users.
